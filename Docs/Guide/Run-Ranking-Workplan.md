# 플레이 기록·랭킹 개선 작업계획

작성: 2026-10-03. 기존 개인 기록 저장·보상·유니온 데이터의 키와 소유권은 유지한다.

## 진행 순서

각 단계는 로컬 회귀 검사 후 Maker Refresh/build/Play 검증을 한다. 2026-10-06 Maker 연결이 복구되어 공개 저장·대상 RPC·UI 이벤트 검증을 수행했다. v3 실제 전투 집계의 전체 런, 출시·다중 인스턴스·모바일·물리 포인터는 아직 미검증이며 구현/단일 Maker 검사와 구분한다.

## 1. 기록 규격

- `CompletedStageNumber`: 기존 호환용 최대 스테이지 번호. 실제 클리어 횟수로 해석하지 않는다.
- `ClearedBattleCount`: 서버가 확정한 승리 건수. 중복 결과/보상 재시도로 증가하지 않는다.
- `Conditions`: 난이도, 밸런스 버전, 시즌, 랭킹 규칙 버전, 계정 성장 적용 구분, 시작 관측 여부. 서버에서 런 시작 때 고정하며 난이도는 초기화 뒤 실제 첫 전투 커밋에서 한 번 확정한다.
- `RegionHistory`: 방문 순서와 지역별 완료 여부·클리어 건수·소비 턴·피격 수. 개별 StageId 목록이나 명령 로그는 저장하지 않는다.
- 기존 v1/v2 저장 JSON은 다시 쓰지 않는다. 새 필드는 읽기 DTO에서 `Captured=false`로 표시한다. 예전 기록의 경로/조건을 추측해서 복원하지 않는다.
- 보유 빌드와 최근 10판 + 별도 개인 최고 보존 정책, 4,000바이트 검증, FIFO 재시도와 인덱스 CAS 경계는 유지한다.

## 2. 리전 집계 경계

1. `BattleGatewayLogic`에서 전투 초기화와 `MarkStarted`가 모두 성공한 후 방문을 기록한다. 이동 선택/실패/단순 맵 입장은 기록하지 않는다.
2. StageDefinitions의 `RegionId`를 그대로 사용한다. ID 문자열에서 지역명이나 숫자를 추출하지 않는다.
3. 같은 지역의 전투/보상/상점 이동은 새 방문을 만들지 않는다. 다른 지역에서 실제 전투를 시작하면 다음 방문을 추가한다.
4. NodeDefinitions의 다음 전투 경계를 따라 지역 종료 여부를 판단한다. 같은 지역의 다음 전투가 남으면 완료가 아니다. 따라서 슬리피우드 6-4 포장마차만 잡아도 지역 전체 완료로 잘못 기록하지 않는다.
5. 진행 집계는 플레이어 컴포넌트가 소유한다. 순수 계약 로직은 검증·복사만, 서비스는 Stage/Node 어댑터만 담당한다. 매 턴 DataStorage를 호출하지 않는다.

## 3. 공개 랭킹 단계의 규칙

- 개인 기록과 공개 랭킹은 다른 기능이다. 기존 `RankEligible`/개인 최고 기록을 곧바로 공개 랭킹 등록으로 해석하지 않는다.
- 첫 공개 랭킹은 같은 난이도·밸런스·시즌·계정 성장 조건의 **완주 기록만** 비교한다. 적은 소비 턴 → 적은 피격 수 순서이며 같은 값은 공동 순위다. 실시간 경과 시간은 표시용이다.
- `BalanceVersion=unversioned`와 과거 조건 미수집 기록은 공개 후보에서 제외한다. 기본 버전을 `balance_2026_10_06`으로 고정했다. 밸런스 변경 시 결과 계약/랭킹 정책의 버전과 별도 BoardId를 함께 갱신한다. 과거 기록에 소급 적용하지 않는다.
- 테스트 시작, 강제 클리어, 시작 미관측, 집계 불완전은 공개 후보에서 제외한다. 테스트 제외는 런 동안 복구되지 않는다.
- MSW 공식 basic/advanced ranking 패키지를 조사했다. 설치에는 기존 PlayerDBManager·UI UUID·입력 레이어와의 영향 확인 및 통합 선택이 필요하다. 패키지를 임의로 설치하지 않는다.
- 사용자가 본인 보존 기록에서 공개 등록을 두 번 눌러 동의한다. 자동 등록하지 않는다. 상위 20명은 30초 서버 캐시, 내 공개 최고는 계정 태그 조회로 별도 표시한다. 개인 최고와 공개 최고 정책은 별개이며 목록 밖 정확한 전체 순위를 약속하지 않는다.
- 다른 사용자의 UserDataStorage 전체 기록을 조회하지 않는다. 공개 동의된 최고 기록만 별도 사본으로 보관해 최근 10판 정리와 분리한다.
- 점수와 공개 사본은 별도 저장 작업이다. 불변 `ProfileCode:RunId` payload를 먼저 쓰고 점수/Tag를 나중에 쓴다. key/tag/score/버전을 검증하고 같은 키 재시도를 허용한다. 중간 실패로 없는 빌드를 가리키지 않으며 동시 저점 기록이 더 높은 별도 키를 덮어쓰지 않는다. 낮은 인덱스는 정리하지만 과거 payload 장기 GC는 이후 작업이다.
