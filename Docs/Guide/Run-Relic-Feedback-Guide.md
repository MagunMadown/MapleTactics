# 런 유물 준비·발동 표시

승인 범위: 기존 유물 UI에 전투용 기념·일반·직업 유물 상태 줄을 추가한다. 전투 효과·수치·획득 정책은 유지한다. MSW 26.10을 유지한다.

- 🟡 RF-01 — 플레이어 소유의 상태·발동 영수증 동기화 구현 및 실제 Lua 검사 통과. Maker 동기화 확인 대기.
- 🟡 RF-02 — 기존 UI에 원본 아이콘·준비 문구·발동 강조 구현 및 빌더 검사 통과. Maker 화면·입력 확인 대기.
- ✅ RF-03 — 실제 Lua 상태/클라이언트 표시 41개, 기존 유물·상점·전투 회귀, 데이터 115개 및 어휘 검사 통과. UI 오류 0·추가 경고 0.
- ⬜ RF-04 — Maker Refresh/빌드/실제 입력·전환·연출 확인. 현재 Maker 실행 MCP 도구가 제공되지 않아 수행하지 못했다. 이번 변경의 Maker 실행 통과를 의미하지 않는다.

## 화면 동작

전투에서 보유한 상태형 유물을 좌측 상단 유물 버튼 아래에 표시한다. 6열·최대 24칸, 각 88×72이며 원본 아이콘과 18px 상태 문구를 사용한다. 준비된 효과는 푸른 배경으로, 실제 발동은 1.2초 동안 금빛 배경과 발동 문구로 강조한다. 강조가 끝나면 현재 준비 상태로 돌아간다.

| 유물 | 상태 문구 | 발동 문구 |
|---|---|---|
| 별조각 | 큐당 1회 / 큐 완료 | 피해 +1 |
| 달조각 | 전환 대기 / 충전 완료 | 충전 / 쿨 -1 |
| 태양조각 | 광역 회복 / 큐 완료 | 회복 +1 |
| 돌조각 | 0/2 / 1/2 / 방어 준비 | 방어 준비 / 피해 -1 |
| 왕관 | 전멸 회복 | 회복 +1 |
| 깃털 | 차단 준비 / 면역 중 / 사용 완료 | 상태 차단 |

표의 수치는 현재 정의 기준이다. 회복·쿨다운 감소·방어는 실제 적용량을 표시하며, 최대 HP나 쿨다운 0에서 적용되지 않은 효과를 발동한 것처럼 표시하지 않는다. 돌조각이 0.5 피해를 전부 줄인 경우에도 실제 감소량 0.5를 유지한다.

유물 창을 열면 상태 줄은 잠시 숨기고 닫으면 현재 상태를 복원한다. 인벤토리의 선택·드래그·정렬은 기존 경로를 유지한다. 상태 줄은 클릭을 받지 않으며 로비·스킬 테스트·에필로그와 이전 런/전투의 데이터는 표시하지 않는다. 전투 종료 직전 발동 영수증은 결과 정산과 함께 수신돼도 표시하고, 그 뒤에는 전투 종료 상태를 표시한다.

## 데이터와 수명

- PlayerRunRelicEffectComponent의 TargetUserSync 문자열 ContentRelicDisplaySnapshot을 사용한다. 기존 InventoryDisplaySnapshot과 분리해 준비 상태 변경이 인벤토리를 재생성하거나 드래그를 취소하지 않게 한다.
- ContentRelicTriggerLogic과 기존 유물 소유자가 판정 직후 공통 RunRelicFeedbackLogic에 통지한다. 전투 효과 상태는 기존 소유자가 유지하고, 표시용 Sequence/Text·소멸 영수증은 플레이어의 RelicFeedbackState가 소유한다. 세션의 계산·실행 책임을 늘리지 않는다.
- 표시 묶음은 RunSequence, BattleKey, Items를 포함한다. Items는 RelicId, DisplayName, IconImageRUID, StateText, Ready, PulseKey, Pulse, PulseText, Transient다. 서버에서 미보유·소진·직업 제한을 걸러낸다.
- 클라이언트는 현재 맵의 동기화된 StageId/EntryRequestId와 소유 플레이어의 RunSequence를 비교한다. 서버 전용 Session.PlayerEntity를 읽지 않는다. 다른 키의 지연된 패킷은 숨긴다.
- 같은 전투의 새 Pulse만 강조한다. 같은 효과를 가진 유물은 PulseKey로 영수증 기준을 공유하며, 판매로 카드가 사라져도 해당 전투의 마지막 기준은 유지한다. 새 유물 획득과 실제 첫 발동이 한 묶음으로 수신되면 그 발동은 표시한다. 처음 표시할 때의 영수증은 기준값으로 받아 이전 발동을 재생하지 않는다. 같은 적 턴에 세 번 차단이 합쳐져 수신돼도 마지막 상태와 강조가 남는다.
- 새 전투에서 초기화하고 웨이브 사이에는 유지한다. 같은 전투 재초기화는 사용한 깃털을 충전하거나 강조를 재생하지 않는다. 판매로 제거된 유물은 상태 줄에서도 빠진다.
- 전용 타이머·입력·RPC는 추가하지 않는다. 기존 ClientOnly UI 갱신에서 강조 시간만 줄이고, 문구·상태가 바뀌거나 강조 중일 때만 렌더러를 갱신한다.

## 로컬 검증

기록: [Lua 검사](../../Artifacts/orbis-relic-feedback/lua-verification.json), [UI 빌더 검사](../../Artifacts/relic-feedback-general/ui-verification.json).

- 실제 운영 Lua 메서드를 실행하고 엔진 JSON/UI/플레이어 경계는 대역으로 교체했다. 달조각 충전·빗나감·다단, 돌조각 진행·이동 유지·감소량, 아이스 3마리 면역·해제, 별조각 단일 발동, 최대 HP 회복 억제, 태양/왕관 회복과 전투 종료 직전 승계, 동일/새 전투·런·판매·모달/맵 변경을 포함한다.
- 기존 오르비스 3,900개와 상점 진열 384개, 5직업 유물 검사, 데이터/리소스 115개, 기존 전투 1,152개 및 피해·상태·소환 회귀가 통과했다.
- UIBuilder로 기존 인벤토리 엔티티 39개의 UUID·구성·배치를 보존한 것을 비교했다. 상태 줄 노드 74개는 입력 통과, 모든 플랫폼 활성, 부모 경계 안의 배치를 확인했다. ui_lint는 오류 0, 기존 경고 6개이며 새 경고는 없다. 제공된 레이아웃 미리보기 도구도 실행했다.
- Balance Studio 어휘 검사와 git diff --check를 통과했다. 새 효과 종류나 획득 종류를 추가하지 않아 어휘 목록은 변경하지 않았다.

재실행은 ORBIS_LUA_PATH에 lupa 설치 경로를 지정한 뒤 Artifacts/orbis-relic-feedback/verify-feedback.py를 실행한다. UI 작성 스크립트는 같은 폴더의 build-ui.cjs다. 런타임 의존성이나 패키지를 게임에 추가하지 않는다.

## Maker에서 남은 확인

1. 정지 상태에서 Refresh 후 build/normal 로그를 모두 확인한다.
2. 두 상점 및 보스 보상으로 얻은 유물만 표시되는지 확인한다. I 키로 유물 창을 열고 드래그·정렬·닫기 후 상태 줄이 복원되는지 확인한다.
3. 일반 방향 전환, 제자리 소비 행동 2회, 큐 끝 직접 명중, 서로 다른 적 2마리 타격, 전멸 웨이브 전환을 실제 입력으로 실행해 상태 문구와 1.2초 강조를 확인한다.
4. 아이스 스톤볼 3마리의 연속 동상 차단에서 상태 차단 → 면역 중 → 사용 완료를 확인한다. 무료/거절 입력은 면역을 끝내지 않아야 한다.
5. 마지막 적 처치로 태양조각이 발동할 때 회복 강조가 결과 정산에 묻히지 않는지 확인한다. 재시작·같은 전투 재초기화·새 전투·로비·새 런에서 오래된 강조가 남지 않아야 한다.
6. PC/모바일 비율에서 골드·유물 버튼·스테이지 배너와 겹침, 원본 아이콘, 한글 가독성 및 입력 통과를 확인한다. 서버 [ContentRelicFeedback], 클라이언트 [ContentRelicHUD] pulse/pulse ended 로그를 함께 수집한다.

기존 기능의 Maker 근거는 이번 HUD의 실행 근거로 대체하지 않는다. 자연 전술 1→16 완주의 회복량·구매 선택 평가도 기존 대기 상태를 유지한다.

## 일반·직업 유물 표시 확장

- 🟡 RF-05 — 첫 방어·유한 방어·생존, 첫 스킬/처치, 처치 누적 및 직업 유물 내부 대기 상태와 발동 연결 구현·로컬 검증 통과. Maker 동기화·화면·입력 검증 대기.
- ✅ RF-06 — 실제 Lua 144개·기존 오르비스 표시 41개·데이터 115개·기존 전투/어휘 및 UI 빌더 검사 통과. 전체 스크립트 4개의 변환 Lua 문법 검사도 통과했다.
- ⬜ RF-07 — 확장된 24칸 상태 줄의 Maker Refresh/변환·빌드, 실제 입력·아이콘·겹침·PC/모바일 가독성 검증. 현재 실행 도구 미제공으로 미수행.

기존 유물 15종의 효과 12유형에 추가 적용했다. 그중 현재 획득이 열린 유물은 10종이며, 레거시 5종은 기존 보유 상태를 표시하는 경로를 지원한다.

| 대상 | 준비·진행 표시 | 발동 표시 |
|---|---|---|
| 냄비뚜껑 / 아이스나이트의 어깨장식 | 준비 완료 → 사용 완료 | 피해 무효 |
| 머리위에 무지개떡 | 방어 3회 → 2회 → 1회 | 피해 무효 / 마지막 방어 소진 |
| 반 레온 워 벨트 | 준비 완료 → 사용 완료 | 체력 1 |
| 이카루스의 망토 / 아이스나이트의 얼음귀고리 | 준비 완료 → 사용 완료 | 실제 쿨 감소량 |
| 하프이어링 / 알테어 이어링 | 준비 완료 → 사용 완료 | 쿨 감소 |
| 말랑말랑한 신발 | 준비 완료 → 사용 완료 | 실제 회복량 |
| 로미오의 펜던트 | 0/3 → 1/3 → 2/3, 런 중 누적 | 실제 회복량 |
| 파워스 메달 | 공격 +0~+3, 전투 누적 | 증가한 공격 수치 |
| 청동화살 | 준비 완료 / 대기 N턴 | 쿨 초기화 |
| 브리즈 페더 | 준비 완료 / 대기 N턴 | 무료 장전 |
| 백금의 서 | 준비 완료 / 대기 N턴 / 장전 예약 | 장전 예약 / 예약 사용 |
| 리스트 밴드 | 준비 완료 / 대기 N턴 | 추가 시전 |

백금의 서는 기존 장전 보너스 예약·소비를 표시한다. 사용한 스킬의 쿨다운이 3보다 짧을 수 있으므로 예약 소비를 항상 쿨 -3으로 표시하지 않는다. 회복·쿨다운 감소는 실제 양수 적용이 있을 때만 강조한다. 파워스 메달의 최대 3스택 이후 추가 처치와 중복 처치는 새 발동으로 강조하지 않는다.

무지개떡은 마지막 방어에서 인벤토리 소멸과 함께 Transient 영수증을 보내 1.2초 강조를 마친 뒤 카드를 숨긴다. 남은 카드가 없으면 상태 줄 제목도 숨긴다. 판매된 유물에는 소멸 영수증을 만들지 않는다.

내부 대기는 기존 EffectReadyTurns와 전투 TurnNumber를 그대로 읽는다. 기존 플레이어 컴포넌트 갱신에서 턴 변경만 관찰해 표시를 갱신하며, 같은 턴에는 추가 표시 묶음을 발행하지 않는다. 효과·수치·획득·행동 소비·쿨다운 계산은 기존 경로를 사용한다. BattleSession에 계산이나 표시 상태를 추가하지 않았다.

검사: [일반 유물 Lua](../../Artifacts/relic-feedback-general/lua-verification.json), [확장 UI](../../Artifacts/relic-feedback-general/ui-verification.json). 재실행 파일은 Artifacts/relic-feedback-general/verify-feedback.py이며 ORBIS_LUA_PATH에 lupa 경로를 지정한다. 최대 HP·쿨다운 0, 자연 무료 장전, 장전 취소/소비, 소멸·판매·동일 효과 재획득, 전투 전환, 직업별 전체 보유와 6개 초과 표시를 포함한다. 24칸은 현재 직업별 전체 상태형 유물을 수용하며, 정의가 늘어 이 수를 넘으면 작성 스크립트와 클라이언트 바인딩 수를 함께 늘린다.

Maker에서는 위 표의 일반/직업 유물을 실제 획득하고, 첫 방어와 무지개떡 3회 소진, 첫 스킬·처치, 스택 최대치, 내부 대기 해제, 자연 무료 장전, 장전 취소·사용, 7개 이상 보유·유물 창 열기를 확인한다. 새 RunRelicFeedbackLogic.mlua의 코드블록은 Maker Refresh가 생성한다. 이번 로컬 문법 검사는 Maker의 mlua 변환·빌드 검증을 대체하지 않는다.
