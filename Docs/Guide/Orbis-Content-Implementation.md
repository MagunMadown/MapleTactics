# 오르비스 콘텐츠 구현

범위: 16단계(일반 14×3웨이브 + 보스 2×1웨이브), 19종, 전투맵 5개. 기존 지역·월드맵 진입 연결 제외. 독립 진행 그래프와 3→4·10→11 중간 상점은 아래 후속 확장에 포함한다. 기준 CoreVersion 26.10.0.0.

## 초기 01~14단계 작업 기록

- ✅ O-01 — 원본 리소스와 15종 모델·모션·스킬·패턴·보스 페이즈 작성, 참조·수치 검사 통과. 실제 연출은 O-05.
- ✅ O-02 — 14단계·38웨이브·맵 라우트·혼합 편성 보장. 실제 Lua 로더에서 모든 3개 배치 변형 검사 통과.
- ✅ O-03 — MapleTile 전반/후반 정원·보스 전용 맵 4개 작성. 지면 연결·소유 UUID·셀 좌표 검사 통과. 실제 착지는 O-05.
- ✅ O-04 — 데이터·실제 로더/스폰 선택·보스 페이즈·기존 전투 회귀의 정적/격리 검사 통과.
- 🟡 O-05 — 초기 01~14 전체의 모델별 시각·보스·이동 검증 대기. 당시 Maker MCP 미연결로 남긴 항목이며, 탑 검증으로 일괄 완료 처리하지 않는다.

초기 01~14단계의 O-05는 당시 Maker MCP 미연결로 실행 검증을 남겼다. 이번 탑 15~16단계의 Maker 검증은 아래 OT-05와 별도 실행 증거로 기록한다.

## 책임과 기본값

- HP/사망 판정: BattleUnitComponent, BattleOutcomeLogic. 모션·피격·사망·피해 표시: BattleUnitPresentationComponent. 보스 페이즈: BossPhaseStateComponent.
- 새 모델은 기존 보드 적과 같은 Transform+Sprite 및 머리 기준점만 제공한다. 물리 AI/StateSet/접촉 피해 경로를 새로 추가하지 않는다.
- 혼합 편성은 슬롯별 지정이 필요하다. StageWaveRepositoryLogic의 기존 랜덤 추첨에 선택적 SpawnIndex를 추가하고 빈 값/0은 기존 가중치 추첨을 유지한다.
- 스테이지/맵 ID는 독립 조회 키다. 초기 작성에서는 운영 NodeDefinitions, 월드맵, 보상/랭킹 연결을 제외했다. 후속 중간 상점 확장은 NodeDefinitions에 독립 orbis_run만 추가하고 기존 prototype_run·월드맵 경로는 유지한다.

## 공통 경로 변경

`EnemySpawnPools.SpawnIndex`는 선택적 열이다. 빈 값/0은 기존 가중 추첨을 유지하며, 양의 정수는 그 순번 슬롯의 후보가 된다. 서로 다른 두 종류를 배치하는 풀은 각각 1·2로 지정했다. 기존 모든 풀의 추첨 결과를 변경 전 로더와 대조했다. Balance Studio의 설명·검사·편성 확률·기대 드롭 계산도 슬롯 단위로 맞췄다. 새 폐쇄형 값은 추가하지 않았다.

`BossPhaseStateComponent`는 체력 임계점에서 페이즈와 증원 시계를 전환하되, 이미 예고한 광역이 있으면 기존 패턴의 후속 공격까지 유지한다. `EnemyTurnExecutionLogic`이 그 공격의 완료 또는 명시적 큐 취소 뒤 보류된 새 패턴을 적용한다. 예고 중·예고 직후·공격 준비 완료·취소를 검사했다. 공개 RPC와 BattleSessionComponent는 변경하지 않았다.

새 맵은 기존 MapleTile(0) 무대에서 평평한 지면 연결을 재사용한다. 셀은 7칸, 간격 1.12, 원점 X=-3.36, 지면 Y=-0.05다. 관련 없는 원거리·위쪽 발판을 제외하고 돌바닥·기둥·구름 장식을 배치했다. 일반 이동·카메라·피격·사망·피해 표시는 기존 공통 경로를 사용한다. SectorConfig에는 전체 5개 물리 맵의 소속만 등록했다. 맵 자동 시작 설정은 유지한다. 후속 중간 상점 확장에서 오르비스 내부 진행 Edge를 추가했다.

## 초기 01~14단계의 남은 Maker 검증

초기 콘텐츠 전체의 다음 항목은 기존 대기 상태를 유지한다. 이번 탑 검증은 15·16단계를 기존 테스트 허브에서 개별 실행했고, 운영 그래프는 추가하지 않았다.

1. Maker Refresh 후 빌드 로그를 확인한다.
2. 임시 단일 스테이지 그래프로 01~14를 각각 실행해 생성·전멸·다음 웨이브·승리/패배·재시작을 확인하고 임시 연결을 제거한다.
3. 보스 예고 중/직후 50%를 통과시켜 기존 피해/범위가 유지되는지 확인한다. 파파픽시 4턴 증원·생존 상한·보스 사망 시 소환수 정리를 확인한다.
4. 15종의 모션·원거리 탄환·효과음·비치명 피격·치명 피해 표시·사망 마지막 프레임/보존을 확인한다.
5. 네 맵에서 좌우 단발/연속/방향 전환·막힌 셀/경계·착지 직후 이동·강제 이동 후 일반 이동·맵 전환을 실제 입력으로 확인한다. 발판·서버 목적 셀/최종 위치·카메라·이름표를 함께 확인한다.

전체 런 연결과 누적 성장 밸런스 검증은 연결 설계 이후 진행한다.

### 탑 Maker 실행 증거 (2026-10-22)

- 테스트 허브의 기존 StartStage 경로로 15·16단계를 독립 실행했다. 실제 출현은 2·2·3 / 2·3·3, 혼합 구성도 일치하며 동시 상한은 3이다. 각각 최종 Victory / ready=true를 기록했다.
- 실제 키 입력으로 이동·방향 전환·스킬 큐·공격을 실행했다. 파이어 명중의 IGNITE 및 스킬 사용 피해, 아이스 3마리 구간의 FROSTBITTEN / CONTROL_RESISTED를 확인했다. 동상 중 이동은 PLAYER_FROSTBITTEN으로 거부됐고, 공격은 성공해 대상 HP 10→8, 1행동 뒤 동상 0과 일반 이동 재개를 확인했다.
- 재진입은 wave=1·적 2·HP 10·화상/동상 0으로 초기화됐다. 실제 피해 경로로 Defeat / ready=true를 만든 뒤 소유 클라이언트 RPC로 lobby 복귀를 확인했다.
- 탑과 로비에서 실제 좌우 입력 후 PlayerGridMovementLogic의 완료·착지 로그를 확인했다. 탑의 지면 Y=-0.049, 정상 착지는 corrected=false였다. 로비도 같은 간격 1.12·이동 시간 0.24초의 공통 경로를 사용했다.

- 기존 상점은 유물 최대 3개와 물약 3종을 방문마다 구성한다. 보유/기구매 유물 제외와 방문별 물약 ID, 가격·수량·재방문 정책을 그대로 사용한다. 앞선 상품표만으로 회복 상품이 없다고 판단한 설명은 정정한다.
- 상점 출발 RPC는 기존 발록 상점과 오르비스 두 상점의 단일 BATTLE/BOSS 연결을 공통 처리한다. 서버가 소유 플레이어·런·현재 상점 맵·실제 다음 노드를 확인하며, 동일 완료 요청은 이동을 다시 만들지 않는다. 실패한 이동은 새 출발 요청으로 재시도할 수 있다. 다른 지역 상점의 월드맵 출발은 유지한다.
- 정적 109개 검사, 기존 Lua 3,900개와 추가 실제 Lua 상점 경로 검사, 상승 난이도 1,152건 및 전투 회귀, Balance Studio 어휘 검사 통과. `verify-shops.py`는 기존 Lua 검사에 이어 그래프·보상·3개 직접 출발 경로(4/11/발록)·무구매·잘못된 맵·중복 완료·실패 재시도·지역 간 출발을 검사한다. 엔진 경계는 대역이며 Maker 검증과 구분한다.
- Maker: 테스트 허브에서 3단계 시작→실제 피해로 전멸→Victory/recorded=true→강화 보상 건너뛰기→첫 상점(visit=1)→출발 UI 이벤트/RPC→4단계 진입 확인. 출발 RPC를 같은 ID로 두 번 요청해도 4단계 진입 요청은 하나였다.
- 같은 런에서 검증 가속을 위해 기존 BattleGateway의 CONTINUE_RUN으로 10단계에 진입했다(4~9 자연 완주 아님). 10단계 전멸→Victory/recorded=true→신규 스킬 선택→두 번째 상점(visit=2) 확인. 골드 부족 시 INSUFFICIENT_CURRENCY로 거부됐고, 임시 런 골드 100 지급 뒤 빨간 물약 1개 구매 및 동일 요청 재전송에서 잔액 90·물약 1개를 확인했다. 출발 후 11단계(orbis_guardian_battle)에서 같은 run=1·visit=2·CLOSED·골드 90·빨간 물약 1·신규 flash_slash 포함 스킬 유지와 orbis_run 노드를 확인했다. Maker 빌드/실행 오류는 0이며 기존 IsPCPlatform 사용 중단 경고 1개는 유지한다.

- 두 보스의 Victory에서 왕관/깃털 1개와 결과 ITEM 이름/썸네일을 확인했다. 중복 호출은 CONTENT_RELIC_ALREADY_OWNED였다. 회복 스킬 보유 QA에서는 충전 1→2, 같은 완료 키 재처리 후 2를 유지했다. 보스 클리어는 공통 ApplyDamage로 가속했다.
- 두 상점에서 2+1·첫 35골드·재열기 동일·구매 후 다음 방문 미보유 추첨·보스 판매 제외를 확인했다. 구매 테스트에는 임시 런 골드를 사용했으며 기존 자연 39골드 검증과 구분한다.
- 최초 테스트 준비 중 잘못된 QA 메서드/필드 호출 3건과 잠긴 mage 직업 진입 시도의 검증 실패를 수정했다. 제품 코드 실행 오류는 없었다. 원시 로그와 제한은 [Maker 기록](../../Artifacts/orbis-content/relic-maker-verification.json)에 보존한다.
