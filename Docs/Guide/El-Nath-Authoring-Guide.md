# 엘나스 제작·테스트 가이드

기준일: 2026-10-20. 브랜치: `feat/jjr/el-nath`.

## 적용 범위

엘나스는 **물리 맵 3개 / 전투 스테이지 6개**로 구성한다. 여섯 개라는 개수는 런타임에
하드코딩하지 않았다. Stage·Wave·Pool CSV 행을 추가하거나 제거해서 조정한다.
다른 지역의 Node, REST, 상점, 캠페인 진행 경로는 이번 작업에서 변경하지 않는다.

기존 `BattleSession`·`BoardState`·`EnemyActionPlan`·스킬 실행기를 재사용한다.
몬스터에 실시간 접촉 공격이나 별도의 AI/FSM을 붙이지 않는다. 몬스터 모델은 외형을 제공하고,
서버 Cell 상태와 공통 연출기가 배치·이동·방향·피격·사망을 담당한다.

## 구성

| 표시 | StageId | 물리 맵 | 웨이브 | 주요 구성 |
|---|---|---|---:|---|
| 7-1 눈 덮인 언덕 | `el_nath_stage_01` | `el_nath_snowfield` | 3 | 주니어 예티 중심, 마지막 혼합 |
| 7-2 페페의 눈덩이 | `el_nath_stage_02` | `el_nath_snowfield` | 4 | 주니어 예티 + 원거리 페페 |
| 7-3 예티의 설원 | `el_nath_stage_03` | `el_nath_ice_valley` | 4 | 예티의 2칸 예고 강타 도입 |
| 7-4 예티와 페페 | `el_nath_stage_04` | `el_nath_ice_valley` | 4 | 탑승형 2회, 처치하면 페페 분리 |
| 7-5 설원 혼성대 | `el_nath_stage_05` | `el_nath_ice_valley` | 5 | 혼합 편성 + 탑승형 2회 |
| 7-6 스노우맨 | `el_nath_stage_06` | `el_nath_boss` | 1 | 임시 보스 스노우맨, 체력 절반 이하 2페이즈 |

모든 스테이지는 7칸, 기본 큐 3칸이다. 일반전은 `LONE_ENEMY`를 사용하므로 한 마리만
남아도 다음 웨이브가 나올 수 있다. 최대 동시 적은 7-1~2가 3, 7-3~5가 4다.
강제 지연 스폰은 각각 7턴/6턴이며, 보스전은 `CLEAR_ONLY`다.
분리된 페페도 살아 있는 적으로 계산하므로 마지막 예티와 페페를 처치한 것만으로 승리하지 않는다.

### 적 체력·공격

기본 난이도 수치이며 기존 유니온/승천 보정은 별도로 적용될 수 있다.

| 적 | HP | 기본 피해 | 패턴 |
|---|---:|---:|---|
| 주니어 예티 | 6 | 1 | 전방 1칸 할퀴기 |
| 페페 | 4 | 1 | 전방 2칸 첫 대상 눈덩이, 쿨 3. 쿨타임이면 부리찍기 |
| 예티 | 8 | 2 | 전방 2칸 강타: 1턴 예고, 피해 2, 쿨 3 → 전방 1칸 내려치기 |
| 예티와 페페 | 9 | 2 | 전방 1칸 강타. 사망하면 HP 4 페페가 같은 칸에 등장 |
| 스노우맨 | 36 | 2 | 주먹 / 냉기 돌풍 / 중단 가능한 눈보라 |

모든 적은 기존 스폰 대기·스킬 장전 규칙을 따른다. 공격을 장전했다고 바로 피해를 주지 않는다.
일반 적은 공통 공격 후 후퇴 규칙을 재사용하고, 뒤로 물러나기 전 방향 전환도 기존 턴 규칙을 따른다.

스노우맨 패턴:

- 주먹: 전방 1칸, 피해 2.
- 냉기 돌풍: 전방 1~2칸, 피해 2 + 동상 1행동, 쿨 3턴.
- 눈보라 집중: 캐스팅 시작 후 다음 실행 단계에서 자신의 칸을 제외한 전 보드 피해 3, 쿨 5턴.
  캐스팅 중 플레이어 스킬에 한 번 유효하게 피격되면 중단된다.
- 1페이즈: 주먹 → 돌풍 → 눈보라 캐스팅/실행 → 대기.
- HP 50% 이하 2페이즈: 돌풍 → 주먹 → 눈보라 캐스팅/실행 → 대기.

`CAST_INTERRUPTIBLE.ParamA=1`은 **중단에 필요한 타수**다. 충전 턴 수가 아니다.
예고·장전·실행은 기존 패턴/큐 단계가 각각 소비한다. `EnemyQueueTurns=0`도 공통 큐에서
최소 장전 규칙을 적용받으므로 즉발 예외로 해석하지 않는다.

## 맵·리소스

맵 타입은 모두 `MapleTile(0)`이다. 설원과 얼음 골짜기는 원작 설원 지형의 서로 다른 구역을
사용하고, 골짜기는 얼음골짜기 계열 배경으로 구분했다. 보스는 원작 차가운 벌판 계열 지형이다.
새 맵에 가져온 원작 몬스터·포털·사다리는 제거하고 공통 전투용 엔티티만 연결했다.

7칸 중심 좌표:

| 맵 | CellStartX | CellSpacing | UnitY | 실제 지면 Y(런타임) |
|---|---:|---:|---:|---:|
| 설원 | 1.9 | 1.12 | 5.29 | 약 5.171 |
| 얼음 골짜기 | -8.9 | 1.12 | 5.29 | 약 5.171 |
| 보스 | 6.9 | 1.12 | 4.09 | 약 3.971 |

`UnitY`는 기존 지면 탐색기의 탐색 시작 기준이다. 몬스터는 공통 지면 탐색으로 발 위치를
맞추고 플레이어는 Rigidbody로 같은 지면에 선다. Cell 링 위치만 바꾸고 지면 좌표를 무시하지 않는다.

외형 모델은 `RootDesk/MyDesk/Models/Monsters/ElNath*.model`이다.
모션은 `EnemyDefinitions`의 Idle/Move/Hit/Attack/Death 필드, 스킬별 모션은
`EnemySkillDefinitions.CasterMotionRuid` 등에서 교체한다. 전용 모션을 우선할 특수기는
기존 `caster_motion` SkillTag를 지정한다. 빠지면 적 공통 AttackMotion이 우선한다.
주니어 예티는 jump, 페페는 move 클립을 짧은 공격 동작으로 재사용한다.
적중 효과·투사체·아이콘은 스킬 CSV, 피격·사망음은 `EnemyImpactPresentations`에서 교체한다.
특수 아이콘 오버레이와 머리 위 큐는 기존 UI를 사용한다.

## 처치 후 분리 규격

`EnemyDefinitions`에 선택 열 두 개를 추가했다. 기존 적은 둘 다 빈 값이므로 동작이 바뀌지 않는다.

| 원본 적 | DeathSpawnEnemyDefinitionId | DeathSpawnModelId |
|---|---|---|
| `el_nath_yeti_pepe` | `el_nath_pepe` | `elnathpepe` |

처리 순서:

1. 기존 적을 사망 처리해 공격·이동·점유에서 즉시 제외한다.
2. `EnemyDefeatSuccessorLogic`이 같은 Cell에 새 적을 한 번 생성한다.
3. 새 적은 새 UnitId, 빈 큐·쿨타임과 스폰 대기를 갖는다. 부모의 준비된 공격을 가져오지 않는다.
4. 기존 처치·드롭 정산을 완료한 뒤 살아 있는 적/웨이브/승리를 판단한다.

검증기는 두 필드 동시 지정, 적 참조, Pool의 정의/모델 조합, 순환 참조, 보스 포함 여부를 확인한다.
생성이 실패하면 데이터 오류로 중단하고 빈 보드라고 잘못 승리 처리하지 않는다.
보스를 분리 체인으로 만들려는 확장은 현재 지원하지 않는다. 모델 실제 등록은 Maker 스폰으로 검증한다.

## 설정 수정 위치

모든 CSV는 `RootDesk/MyDesk/03_Data/` 아래다.

- 스테이지 추가/제거·칸 수·시작점: `StageDefinitions`, `StageMapRoutes`.
- 웨이브 수·마릿수·지연 스폰·최대 동시 적: `StageEnemyWaves`.
- 몬스터 출현 비율: `EnemySpawnPools.Weight`.
- HP·공격력·모션·분리 대상: `EnemyDefinitions`.
- 사거리·쿨·아이콘·모션·이펙트: `EnemySkillDefinitions`, 실제 피해/상태는 `SkillEffectSteps`.
- AI 단계·예고·중단 타수: `EnemyPatternSteps`; 보스 체력 경계는 `BossPhaseDefinitions`.
- 드롭/클리어 골드: `EnemyDropDefinitions`, `StageRewardDefinitions`.

StageId는 조회 키로만 취급한다. 이름에서 숫자나 지역을 추출하지 않고 RegionId/StageIndex/StageType을 읽는다.
새 맵을 추가하면 Maker Sector 등록도 확인한다. 현재 3개 맵은 등록돼 있다.

## 직접 테스트

1. Maker에서 `battle_test_hub`를 열고 실행한다.
2. 공용 테스트 화면에서 `el_nath_stage_01`~`06`(표시 이름 7-1~7-6), 직업·시드를 선택한다.
3. 테스트 시작으로 진입한다. 카탈로그가 StageDefinitions/StageMapRoutes를 읽으므로 별도 목록 하드코딩은 없다.
4. 빠르게 확인하려면 Maker에서 새 물리 맵을 직접 열고 실행한다.
   설원은 7-1, 골짜기는 7-3, 보스맵은 7-6을 시작한다. 공유 맵의 7-2/4/5는 테스트 허브에서 선택한다.

실제 런 경로는 아직 연결하지 않았으므로 클리어 후 다음 지역이나 REST로 이동하는 것은 테스트 대상이 아니다.
기록 관찰기의 `STAGE_NODE_NOT_FOUND` 경고는 Node 미연결 때문이며 이번 단계에서는 예상된다.

## 검증 현황

- 정적 CSV/참조·회귀 테스트 106개 통과, Balance Studio vocabulary 검사 통과.
- Maker: 시작 콘텐츠 검증 VALID. 구조 검증과 별도로 일반 HUD 명령만 사용한 6개 스테이지 Victory 확인.
- 분리 4회: 같은 Cell·새 UnitId·빈 큐·스폰 대기, 중복 호출 시 한 마리만 생성 확인.
- 일반 적 4종: 피격 클립, 스폰 대기, 장전, 방향 전환과 공격/후퇴 단계 확인.
- 스노우맨: 36턴 진행, 중단 1타, 중단 시 피해 0, 미중단 눈보라 피해 3·쿨 5, 2페이즈 확인.
- 세 물리 맵: 실제 클라이언트 이동 요청으로 3→4→3, 지면 높이·접지 및 2행동 소비 확인.
- 특수기 3종: 예티 강타·스노우맨 돌풍·눈보라 각각 전용 클립 재생 확인. 예티 예고 회피 시 피해 0.

최초 구조 검증의 직접 피해 호출은 밸런스 클리어 근거에서 제외한다. 이후 수행한
[엘나스 전투 밸런스 검증](El-Nath-Balance-Test-Report.md)은 실제 전사 스킬 장전·큐 실행·이동·방향 전환·
직업 방어 명령만 사용했다. NORMAL / HP 10 / 2단계 스킬 3개 / 시드 7101에서
7-1~7-6을 모두 클리어했다. 테스트는 스테이지별 새 런이며 연속 캠페인 검증은 아니다.
1단계 스킬 3개로는 7-5를 HP 5/10으로 클리어했고, 7-6은 보스 HP 4를 남기고 패배했다.
추가 검증을 합쳐 실제 전투 9회 중 8승·1패·진행 정지 0건이다. 마법사는 계정 잠금 때문에 미실행했다.
이후 Maker 허브 한정 잠금 예외로 마법사 7-1 시작·스킬 피해를 별도 확인했으며, 마법사 전체 클리어 검증은 아니다.
이 표본만으로 모든 기본 스킬 구성의 난이도를 보장하거나 보스 수치를 임의로 변경하지 않는다.
자동 정책은 클리어 가능성을 보여주지만 배경 구도, 아이콘 크기, 모션 감각과 사람의 체감 난이도는
추가 플레이 리뷰가 필요하다. 다른 직업·시드·승천 난이도는 별도 검증 범위다.
기존 공통 피격/사망 연출 전체 감사(보호 동작 중 피격·다단히트·사망 대기 경합)는 이번 지역 추가와
분리 기능의 검증으로 대신하지 않으며 기존 미확인 항목을 그대로 유지한다.
특히 기존 공통 `ApplyDamage`의 치명타 HIT→사망 처리 순서까지 이번 변경으로 인증한 것은 아니다.
해당 전역 연출 감사는 프로젝트 루트의 `.maplestory-skill-maker-ledger.md`에 열린 항목으로 남겼다.
