# 런타임 로그 운영 가이드

## 원칙

개발 중에는 실행 경로를 확인할 수 있는 로그를 추가한다. Maker에서 정상·실패 경로를 검증하고 결과를 작업 기록에 남긴 뒤, **완성된 기능의 임시 디버그 로그를 같은 작업에서 삭제한다.** 로그는 기능의 출력이나 공개 상태 API를 대신하지 않는다.

완성된 기능의 기본값은 조용한 정상 실행이다. 로그는 실제로 문제를 찾거나 운영 상태를 판단하는 데 필요한 최소한만 유지한다.

## 남기는 로그

| 상황 | 수준 | 기준 |
|---|---|---|
| 필수 Dataset 누락, 잘못된 참조, 상태 불변식 위반, 복구 불가능한 처리 실패 | `log_error` | 원인과 대상 ID를 적는다. 반환값·오류 코드와 일치시킨다. |
| 예상 밖이지만 안전한 기본값으로 복구한 경우, 리소스 로드 실패 등 조치 가능한 이상 | `log_warning` | 복구 내용과 영향 범위를 적는다. 같은 원인이 반복되면 중복 출력을 막는다. |
| 시작 시 설정 로드 결과, 드문 주요 상태 전환 등 장기 운영에 필요한 사건 | `log` | 소유자별로 한 번만 남기고 ID·결과를 포함한다. 같은 정보가 이미 상위 요약 로그에 있으면 생략한다. |

잘못된 입력·쿨타임·막힌 이동처럼 **정상적으로 예상되는 거절**은 기본적으로 반환값의 `Success`/`Reason`과 UI 피드백으로 전달한다. 부정행위 의심이나 반복 실패 분석 등 명확한 운영 목적이 있을 때만 별도 로깅을 설계한다.

## 삭제하는 로그

완료 전 로그 정리에서 다음 항목을 우선 찾는다.

- `OnUpdate`, HUD Refresh, 속성 동기화, 애니메이션 프레임마다 출력하는 상태 스냅샷.
- 매 타격·이동·큐 슬롯·아이콘·툴팁 렌더링마다 찍히는 성공 로그.
- Repository의 **조회 또는 행 변환마다** 찍히는 `loaded`, Validator의 **행마다** 찍히는 `valid`.
- 같은 결과를 Session·Repository·UI에서 중복으로 출력하는 로그.
- 테스트용 `ready`, `entered`, `played`, 변수 덤프와 임시 분기 확인 로그.

로그 호출을 지운 뒤 그 문자열 조합만을 위해 계산하던 변수도 함께 지운다. 단, 실제 UI·판정에 쓰이는 값은 보존한다. `log_warning`·`log_error`를 단순히 전부 삭제하지 말고 원인별로 판단한다.

## 기능별 완료 절차

1. 작업 중에는 실행 여부를 확인할 지점에 임시 `log()`를 추가한다. Tag와 핵심 ID·결과를 포함한다.
2. Maker에서 정상 경로, 실패 경로, 종료·맵 이동 경로를 실행한다. 빌드 오류와 런타임 오류를 확인한다.
3. 확인한 로그와 예상값을 PR 설명, 작업 기록 또는 기능 가이드에 남긴다. 증거를 남겼다면 코드에 임시 로그를 계속 둘 필요는 없다.
4. 위의 반복 성공 로그를 삭제하고, 남은 로그의 빈도·중복·조치 가능성을 검토한다.
5. Refresh/빌드 후 핵심 경로가 계속 동작하는지 확인하고, 완료 기록에 “로그 정리 완료”를 포함한다.

문제 재현을 위해 상세 추적이 다시 필요하면 해당 기능에만 임시로 추가하고, 수정·검증이 끝나면 다시 삭제한다. 영구 디버그 플래그나 전역 상세 로그는 실제 사용 사례와 소유자가 정해진 경우에만 추가한다.

## 예시

```lua
-- 개발 중: 특정 분기의 실행 증거로 잠시 사용하고 검증 후 삭제
log("[BattleQueue] refresh revision=" .. tostring(revision))

-- 유지: 조치할 수 있는 데이터 오류
log_error("[DamageSkinData] rejected row=" .. tostring(rowIndex) .. " reason=" .. reason)

-- 유지 가능: 시작 시 한 번 발생하며 설정 로드를 확인하는 요약
log("[DamageSkinData] loaded count=" .. tostring(#definitions))
```

새 로그를 추가할 때는 **“누가 이 로그를 보고 어떤 조치를 하나?”**에 답할 수 있어야 한다. 답이 없으면 반환값, 상태 DTO, 기능 가이드의 검증 기록으로 충분한지 확인한다.
