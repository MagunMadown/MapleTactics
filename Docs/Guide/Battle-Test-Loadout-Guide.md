# 전투 테스트 시작 로드아웃 안내

## 이 기능은 무엇인가요?

`battle_test_hub`는 Maker Play에서 전투 시작 조건과 시작 스킬을 빠르게 바꿔 보는 공용 테스트 시작 화면입니다.
Stage, 직업, seed를 고른 뒤 기본 시작 또는 커스텀 시작을 선택할 수 있습니다.
이 안내는 테스트 시작 시점의 로드아웃을 설명합니다.
전투 중 이동, 턴 진행, 스킬 사용 규칙은 기존 전투 규칙을 따릅니다.

## 화면에서 고르기

1. Maker에서 `battle_test_hub` 맵을 연 뒤 Play를 실행합니다.
2. 시험할 Stage를 선택합니다.
3. 직업을 선택합니다.
4. 재현 가능한 조건이 필요하면 seed를 `-100` / `+100` 버튼으로 조정합니다.
5. 기본 시작 또는 커스텀 시작 모드를 고릅니다.
6. 선택을 마친 뒤 화면의 시작 동작으로 전투를 시작합니다.

직업을 바꾸면 모드와 관계없이 현재 로드아웃 선택은 초기화됩니다.
직업을 바꾼 뒤 Stage와 seed를 다시 확인하고 스킬을 선택하세요.

### 테스트 허브에서의 직업 잠금

Maker Play의 `battle_test_hub`에서 시작하면 잠긴 직업도 테스트할 수 있습니다.
기본 시작·커스텀 시작 모두 적용되며, 계정 직업을 실제로 해금하거나 해금 토큰을 사용하지 않습니다.
예외 권한은 서버가 만든 해당 `NEW_RUN` 시작 요청에만 붙고, 목적지 전투 초기화 중에만 유효합니다.
시작 완료·취소·새 요청 준비·초기화 때 제거됩니다.

로비 시작, 전투 맵 직접 Play, 운영 월드에서는 기존 직업 잠금을 그대로 적용합니다.
프로필 로딩 실패나 잘못된 직업/스킬 데이터는 이 예외로 무시하지 않습니다.

개발 시 공통 `CanSelectJob`의 잠금 정책을 풀지 마세요. `RunManagerLogic.ApplyJobSelection`은
`JOB_LOCKED`일 때만 `BattleTestHubLogic.CanBypassJobLock`에 예외 여부를 위임합니다.
이 판정은 서버 관리 요청 번호·직업·초기화 상태·목적 맵을 모두 확인합니다.
`PrototypeTestMode` 또는 Maker 여부 하나만으로 공통 잠금을 우회하도록 확장하지 않습니다.

## 기본 시작 모드

기본 시작은 선택한 직업의 기존 시작 스킬 규칙을 사용합니다.
시작 스킬은 직업별 시작 스킬 데이터에 따라 정해집니다.
일반 계정에서 적용되는 시작 스킬 랜덤 선택 규칙도 기존대로 유지됩니다.
계정 보너스 역시 기존 규칙대로 처리됩니다.
따라서 이 모드는 일반적인 기본 시작 결과를 재현하거나 확인할 때 사용하세요.

## 커스텀 시작 모드

커스텀 시작에서는 최대 6개의 시작 스킬 슬롯을 직접 구성합니다.
여기서 6칸은 보유 스킬바이며, 공격을 담는 큐의 최대 크기는 기존 직업/스테이지 규칙 그대로입니다.
각 슬롯의 좌우 버튼으로 해당 직업의 일반 스킬을 살펴보거나 빈 슬롯을 선택할 수 있습니다.
목록은 현재 선택한 직업의 스킬 데이터만 대상으로 하며, 마법사의 힐도 포함됩니다.
스킬을 선택한 다음 `+`와 `-` 버튼으로 강화 단계를 조정합니다.

강화 단계 표시는 해당 스킬의 실제 CSV 정의를 기준으로 합니다.

| 표시 단계 | 의미 |
| --- | --- |
| 1단계 | 기본 스킬, 강화 없음 |
| 2단계 | 기본 스킬에서 한 번 강화 |
| 3단계 | 기본 스킬에서 두 번 강화 |

강화 단계는 임의 숫자를 입력해 정하는 값이 아닙니다.
해당 스킬의 CSV에 실제 정의된 다음 강화가 있을 때만 단계를 올릴 수 있습니다.
현재 CSV 경로에 정의된 마지막 강화 단계가 선택 가능한 최댓값입니다.
최댓값을 넘겨 더 강화하거나 데이터에 없는 단계를 지정할 수 없습니다.
강화가 정의되지 않은 스킬은 기본 단계로만 시작할 수 있습니다.

## 슬롯과 스킬 선택 규칙

- 빈 슬롯은 스킬을 배정하지 않는 슬롯입니다.
- 최소 1개의 스킬은 선택해야 시작할 수 있습니다.
- 같은 스킬을 기본 단계와 강화 단계로 나누어 여러 번 넣을 수 없습니다.
- 같은 스킬을 여러 슬롯에 중복해서 넣을 수 없습니다.
- 다른 직업의 스킬은 선택할 수 없습니다.
- 적 전용 스킬은 선택할 수 없습니다.
- 직업 특수 능력은 공격 스킬 슬롯에 넣을 수 없습니다.
- 공격 스킬과 그 강화 단계는 기존 직업별 스킬 데이터에 있는 항목만 선택할 수 있습니다.

### 시작 스킬 3개 버튼

`시작 스킬 3개` 버튼은 선택한 직업의 `JobStartingSkillEntries` 중 `SlotIndex` 1, 2, 3을 가져옵니다.
세 항목은 모두 기본 단계로 설정됩니다.
이 버튼은 해당 세 슬롯을 불러오는 고정 리셋 동작입니다.
일반 계정 기본 시작에서 발생할 수 있는 랜덤 시작 스킬 선택과는 다릅니다.
따라서 테스트 중 세 슬롯을 같은 기준 구성으로 되돌릴 때 사용하세요.

## 적용 범위와 데이터 안전

커스텀 시작은 Maker Play 테스트 용도로만 사용할 수 있습니다.
커스텀 로드아웃은 새 전투 시작 요청 중 해당 `NEW_RUN` 진입의 `RequestId`에만 적용됩니다.
커스텀 스킬·강화 선택 자체는 계정에 영구 지급하거나 저장하지 않으며 직업 해금도 변경하지 않습니다.
랭킹 제외는 기존 `PrototypeTestMode` 규칙을 따릅니다.
단, 이것이 모든 공통 플레이 기록의 저장을 막는다는 뜻은 아닙니다.
기존 몬스터 도감의 발견 기록은 별도 경로이므로 테스트 처치로도 갱신될 수 있습니다.
기본 시작 모드는 기존 계정 보너스와 직업 시작 규칙을 유지합니다.
화면의 커스텀 선택은 해당 Play 동안 유지되며, Play 종료 후에는 별도로 저장하지 않습니다.

전투가 시작된 뒤에는 기존 강화 스킬 데이터를 그대로 사용합니다.
이 기능은 이동 구현이나 전투 중 스킬 처리 방식을 바꾸지 않습니다.
`StageDefinitions`와 `StageMapRoutes`에 등록된 전투 Stage는 허브에서 같은 설정으로 테스트할 수 있습니다.
이 기능은 실제 캠페인의 맵 이동 경로를 새로 연결하거나 바꾸지 않습니다.
로비 또는 전투 맵 직접 Play 경로에는 허브의 커스텀 선택을 적용하지 않습니다.

## 데이터 기준

선택 가능한 시작 스킬은 `JobStartingSkillEntries`와 직업별 `*SkillDefinitions` 데이터를 기준으로 합니다.
강화 가능 여부와 다음 단계는 `SkillTier`, `BaseSkillId` 및 기존 `GetNextSkillUpgrade` 흐름을 따릅니다.
별도의 로드아웃 CSV 스키마나 임의 강화 단계 규격은 추가하지 않습니다.
따라서 데이터에 없는 스킬 또는 강화 단계는 화면에서 선택할 수 없습니다.

## 빠른 테스트 체크리스트

- Stage, 직업, seed를 선택하고 기본 시작이 기존 규칙을 사용하는지 확인합니다.
- 직업 변경 후 선택이 초기화되는지 확인합니다.
- 커스텀 모드에서 빈 슬롯과 직업 공격 스킬을 선택합니다.
- `+`와 `-`로 기본 및 CSV에 정의된 강화 단계만 오가는지 확인합니다.
- 강화 경로의 마지막 단계에서 더 이상 증가하지 않는지 확인합니다.
- 동일 스킬 중복을 넣을 수 없는지 확인합니다.
- `시작 스킬 3개`가 시작 항목 SlotIndex 1~3의 기본 단계로 돌아가는지 확인합니다.
- 시작 후 이동과 전투가 기존 강화 스킬 데이터를 사용하는지 확인합니다.
- 커스텀 스킬 구성이 영구 지급/직업 해금으로 이어지지 않고 랭킹 제외 플래그가 유지되는지 확인합니다.
- Maker 허브에서 잠긴 직업의 기본·커스텀 시작이 가능하고, 시작 후 계정 잠금은 유지되는지 확인합니다.

## 검증 상태

2026-10-20 Maker Play에서 다음을 확인했습니다.

- 테스트 UI 버튼 이벤트 → 서버 RPC → 엘나스 7-1 진입 → 강화 스킬바 적용
- 브레이브 슬래시/디바인 차지 지급, 빈 슬롯 위치 유지, 실제 큐 등록·실행
- 직업 변경 시 초기화, CSV 마지막 단계에서 증가 제한, 힐의 가짜 강화 경로 제외
- 다른 직업/적 스킬, 동일 계열 중복, 0개 선택, 슬롯 수/길이 오류 거절
- 잘못된 요청이 새 런 준비 전에 차단되고, 오래된 RequestId·전투 중 재설정이 거절됨
- 시작 완료·취소·재준비·초기화 시 pending 커스텀 데이터 제거
- 커스텀 전투 이후 기본 시작으로 재진입 시 강화 설정이 새 런에 남지 않음

직업 잠금 예외 추가 검증(2026-10-20):

- 실제 계정에서 `JOB_LOCKED`인 마법사로 기본 시작, HP 7·기본 스킬 적용·실제 피해 2 확인
- 같은 계정으로 샤이닝 레이/아이스 스트라이크/익스플로전/힐 커스텀 시작, 실제 피해 4 확인
- 시작 후 계정은 계속 `JOB_LOCKED`, 일반 `ApplyJobSelection`도 거절, 요청의 예외 권한은 0으로 해제
- 허브 밖에서는 예외 권한 미발급, 오래된 요청 거절, 새 준비·취소·초기화 시 권한 제거 확인
- 정적 검사 110개 통과(기존 데이터 검사 106개 + 시작 권한 경계 검사 4개)

운영 월드의 Maker 아님 분기는 코드 경계로 검토했으며, 운영 배포 후 실플레이를 수행한 것은 아닙니다.

검증은 Maker 전용이며 운영 월드의 계정 데이터 쓰기나 직업 해금 규칙을 새로 변경하지 않습니다.
기존 도감 등 공통 플레이 기록 경계는 위의 적용 범위 설명과 별도로 확인해야 합니다.
