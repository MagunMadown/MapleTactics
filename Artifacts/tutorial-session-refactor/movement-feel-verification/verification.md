# 홉 배율 통일·맵별 이동 검증

검증일: 2026-10-12 / CoreVersion: 26.10.0.0\
범위: 사용자 요청 1번 배율 통일, 2번 도구로 가능한 이동·입력·추종 검증. 실제 PC 포인터는 사용자 요청으로 유예했다.

## 결과

- **1번 통과**: BattleSessionComponent의 PlayerHopAnimationPlayRate 기본값을 3→1로 바꿨다. 로비의 공통 프로필 1배와 일치하며, 20개 전투맵 모두 설정과 실제 MoveHopAnimation 이벤트 배율이 1배다. 추가 관찰한 6개 전투맵·로비에서 실제 AvatarBodyActionSelector의 Fall 상태와 AvatarRenderer 배율 1도 확인했다.
- **2번 도구 검증 통과, 사람의 화면 체감 검토는 남음**: 기본 이동 41회·서버 착지 검사 41회가 모두 일치하고 보정 0회. 20개 맵의 양쪽 경계와 대표 점유 셀 거절에서 셀·루트·턴이 유지됐다.
- 전투 20개 맵×반전/착지 직후 입력 2개 = **40개 정밀 이벤트 검사**. 3,439개 타이머 좌표 샘플에서 아바타/등록된 이름표·HP 추종 루트의 상대 오차는 0이었다. 로비의 추가 178개 샘플도 오차 0이었다.
- 이동 회귀 37개 + 실제 세션/로비 기본값 프로필 비교 1개 + 제어·이동 회귀 20개 통과. Maker 최종 build 오류 0, 유효 검사 제품 runtime 오류 0. 직접 LSP 도구는 제공되지 않아 별도 LSP 호출은 하지 않았다.
- 최종 Maker는 로비의 편집 모드다. 미완료 이동·반동과 이전 전투의 이동/착지 검사는 없고, 플레이어 카메라 Damping은 (2.5, 3.9)로 복원됐다.

## 변경

이번 게임 소스 변경은 BattleSessionComponent의 홉 배율 기본값 한 줄이다. 공개 메서드 288개와 인자·실행 공간을 유지했다. 공통 이동 시간 0.24초, 높이 0.30, LINEAR 곡선, 착지 유예/보정 정책은 유지했다.

회귀 fixture가 공통 프로필을 그대로 복사해 세션 기본값 차이를 숨기던 점을 보완했다. grid-movement-latency-test.py가 실제 세션 기본 선언을 읽어 로비와 전투의 전체 프로필을 비교한다. 기존 요청 소유권·현재 맵·셀·턴 검증을 유지했다.

## 빠른 반전·착지 직후·연속 입력

정밀 검사는 Maker execute_script에서 InputService.SendEvent(KeyDownEvent)를 타이머로 전달했다. **물리 키보드의 정밀 타이밍 시험이 아니다.** Maker keyboard_input 예약 두 호출은 실제 전달 간격 약 1.94초여서 빠른 반전 증거에서 제외했다.

- 100ms 예약 반전의 실제 전달은 전투 **0.100~0.175초**, 로비 **0.105초**였다. 전투는 진행 중 추가 이동을 만들지 않았고, 로비는 한 번 버퍼링해 돌아왔다.
- 전투 착지 직후 입력은 RootLanded를 관찰한 **0.243~0.309초**에 보냈다. 완료 응답·적 턴이 남아 있는 동안 중복 이동이 없었다.
- READY 뒤 입력은 **0.445~3.571초**에 전달됐다. 커닝시티 일반전·슬리피우드 사원 전투에서는 적의 목적 셀 점유로 정상 CELL_OCCUPIED 거절을 받았고, 나머지는 다음 이동이 시작됐다. 턴 대기 시간과 이동 재생 시간을 구분한다.
- 로비는 착지 시점 0.241초 입력을 버퍼링하고, 다음 입력 가능 시점의 별도 입력도 한 칸씩 처리했다. 두 경계의 X=-34.0886/-17.2886에서 루트 이동 없이 반동이 복원됐다.
- skill_test에서 기존 유틸리티 선택 API로 teleport를 지정한 뒤 실제 S키로 Cell 2→4 순간이동을 했다. A/D를 각각 700ms 눌러 Cell 4→3→4로 한 번씩 이동하고 두 착지 검사 보정 0을 확인했다.
- 이동 중 0.02149초 시점에 로비 전송을 예약했다. MAP_CHANGED로 클라이언트 요청이 정리되고 이전 세션의 이동/착지 검사도 제거됐다. 최종 클라이언트·서버 위치는 (-27.3686,-6.769,0)이며 오래된 위치 복원은 없었다.

## 화면·추종 관찰의 범위

최종 기본 이동 172개 샘플과 전투/로비 정밀 타이머 샘플에서 등록 추종 루트의 상대 좌표 오차가 0이었다. 이름/HP 자식 좌표 변화도 0이었다. 실제 활성 BattleCameraAnchor의 좌표 유지와 플레이어 카메라 설정 복원을 확인했다. **렌더된 카메라 궤적은 측정하지 않았다.**

perion_03_battle-idle.png와 lobby-right-boundary-idle.png는 정지 장면의 가독성 근거다. 0.24초 이동 전체의 렌더 부드러움·한 프레임 떨림이 없다는 근거로 사용하지 않는다. 타이머 호출·스크립트 좌표 샘플을 GPU FPS로 표현하지 않는다.

초기 고정 시각 루트 참조 관찰에서 상대 오차 0.16339가 잡혔다. 현재 시각 루트를 매 샘플 재조회한 엘리니아 재검증과 타이머 관찰에서는 재현되지 않았다. 초기 측정 오차의 원인은 확정하지 않았으며, 사람의 화면 체감 검토는 남긴다.

## fixture와 관찰 오류

- 런타임에서 대상 세션의 RequireValidContentAtStartup=false와 PrototypeTestEntry로 이동 검증 진입을 준비했다. 콘텐츠/해금/전체 정상 런의 검증은 아니다. 기존 요청 소유권·현재 맵·셀·턴 판정은 유지했다.
- 검사 사이 HP를 복구했고, 경계 점유자가 있으면 기존 서버 API로 빈 칸에 옮겼다. 모든 override는 Play 메모리이며 게임 파일에 저장하지 않았다.
- 저장은 UnionProfile:MoveFeelVerify20261012E/F 키에 격리했다. 기본 저장 키나 기존 튜토리얼 완료 기록을 초기화하지 않았다.
- mage 진입은 기존 JOB_LOCKED에 막혀 제외했고 warrior로 다시 진입했다.
- 제품 오류와 별도로 관찰/fixture runtime 오류 2개를 보존했다. 첫 fixture는 턴 종료를 기다리지 않아 FIXTURE_NOT_READY를 출력했으며 대기 후 재검증했다. 첫 맵 전환 관찰은 이탈한 세션의 GetBattleUiState를 읽어 nil 호출을 냈으며 현재 맵 일치 조건을 추가하고 **동일 전환 오류 0**으로 재검증했다.
- Play 시작 직후 아직 실행 컨텍스트가 없어 한 번 미디스패치됐다. 실제 context 키가 생긴 뒤 다시 실행했다. 대용량 증거 저장은 도구 입력 크기 제한에 맞춰 분할 저장했다.
